# AGENTS.md

## Project Overview

Ramadan Countdown is a [TanStack Start](https://tanstack.com/start) application that provides a countdown to the next Ramadan, deployed to Cloudflare Workers. Ramadan dates are stored directly in TypeScript code at `src/data/ramadan.ts`.

### Architecture: static-first for traffic spikes

The site historically gets ~100k visitors/day around Ramadan. To stay within Cloudflare Workers request limits:

- Both pages (`/` and `/eid`), in every supported language, are **prerendered at build time** (`prerender` in `vite.config.ts`) and served as static assets. Static asset requests are free and unlimited on Workers and never invoke the Worker.
- Only `/api/*` requests invoke the Worker.
- All SEO copy (titles, descriptions, the "N days from today" answer sentence, FAQ text, JSON-LD) is computed at build time from the `__BUILD_DATE__` constant injected in `vite.config.ts` (logic in `src/utils/seo.ts`). Using one shared timestamp keeps the prerendered HTML and the hydrating client bundle identical, so there is no hydration mismatch.
- CI runs a **daily scheduled rebuild** so the baked-in day counts stay fresh, `public/sitemap.xml` (generated by `scripts/generate-sitemap.mjs` during `pnpm build`, gitignored) gets a new `lastmod`, and the copy switches phases automatically: countdown before Ramadan, day tracker during Ramadan, Eid greetings on Eid.
- `wrangler.jsonc` sets `assets.html_handling: "drop-trailing-slash"` so the prerendered `eid/index.html` is served at `/eid`, matching the canonical URL and sitemap.

## Internationalization (i18n)

The site is translated into the five most-spoken world languages. English is the default at `/` and `/eid`; the others are served under a path prefix.

| Locale | Language | Home | Eid | Dir |
| --- | --- | --- | --- | --- |
| `en` | English (default) | `/` | `/eid` | ltr |
| `ar` | Arabic | `/ar` | `/ar/eid` | rtl |
| `es` | Spanish | `/es` | `/es/eid` | ltr |
| `hi` | Hindi | `/hi` | `/hi/eid` | ltr |
| `zh` | Chinese (Simplified) | `/zh` | `/zh/eid` | ltr |

- **Config**: `src/i18n/config.ts` holds `LOCALES`, `LOCALE_META` (html lang, dir, Intl date locale, og:locale, native name), and the URL/hreflang helpers.
- **Messages**: each locale implements the `Messages` contract in `src/i18n/messages/types.ts`. `en.ts` is the reference and its strings must match `src/utils/seo.test.ts`. The phase logic (countdown / day tracker / Eid) lives once in `src/utils/seo.ts`; only the words are per-locale.
- **Dates**: `makeDateFmt` in `src/utils/date.ts` formats via `Intl` with `numberingSystem: 'latn'`, so every locale shows Latin digits (matching the countdown boxes) with localized month/weekday names, in UTC.
- **Runtime**: `__root.tsx` derives the locale from the pathname to set `<html lang dir>` and provide `I18nProvider`. Components read strings via `useI18n()`. English lives in `src/routes/{index,eid}.tsx`; the other locales share the same page bodies (`HomeView` / `EidView`) through the `src/routes/$locale/` routes, which 404 unknown locales (and `/en`).
- **SEO**: `buildPageHead` in `seo.ts` emits the per-locale canonical, `og:locale`, and `hreflang` alternates (all locales + `x-default`). `scripts/generate-sitemap.mjs` lists every locale URL with `xhtml:link` alternates.

**To add a language**: add it to `LOCALES` + `LOCALE_META` (`config.ts`), create `src/i18n/messages/<locale>.ts` and register it in `messages/index.ts`, add its two paths to `pages` in `vite.config.ts`, and add it to `LOCALES` in `scripts/generate-sitemap.mjs`.

## Setup & Development

- **Install dependencies**: `pnpm install`
- **Start dev server**: `pnpm dev` (http://localhost:3000)
- **Build project**: `pnpm run build` (vite build + prerender + `tsc --noEmit`)
- **Preview production build**: `pnpm preview` (runs in workerd via the Cloudflare Vite plugin)
- **Deploy**: `pnpm run deploy` (requires Wrangler auth for the personal Cloudflare account)

## Code Style & Linting

- **Formatter/Linter**: [Biome](https://biomejs.dev/)
  - Run check: `pnpm lint`
  - Apply fixes: `pnpm exec biome check --apply .`
- **TypeScript**: Strict mode. Use Zod for input validation (see the API routes).
- **Styles**: Tailwind CSS v4 (configured in `src/styles/app.css` via `@theme`, no tailwind.config file).
- **Conventions**:
  - File-based routes live in `src/routes` (TanStack Router). `src/routeTree.gen.ts` is generated — never edit it.
  - Page routes use `component`; API routes use `server.handlers`.
  - Keep logic in `src/utils`; data types in `src/data/ramadan.ts`.
  - Prefer functional components and React hooks.

## Testing

- **Framework**: Vitest.
- **Run tests**: `pnpm test`
- Test files follow the `*.test.ts` naming convention (see `src/utils/ramadan-state.test.ts`).

## Data Structure

- Ramadan data is stored in `src/data/ramadan.ts` as a TypeScript array.
- Each entry contains: year, hijriYear, ramadanStart, ramadanEnd, and eidAlFitr dates.
- To add a new year, add a new entry to the `ramadanData` array and deploy.

## API Endpoints

Defined as TanStack Start server routes in `src/routes/api/`:

- `/api/countdown`: Returns current countdown data (accepts `?timezoneOffset=`).
- `/api/ramadan`: Returns whether today is Ramadan (accepts `?timezoneOffset=`).
- `/api/history`: Returns all known Ramadan dates.

These are public JSON APIs with open CORS — keep response shapes backward compatible.
